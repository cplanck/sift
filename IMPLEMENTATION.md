## Architectural decisions

- UI refinement: a centered searchable library replaces the sidebar and uses responsive photo cards, optional compact rows, favorites and lifecycle filters. A small persistent voice button has a separate chevron for the text panel; the existing conversation and voice runtime remains shared. Streamed Markdown, thinking/tool states, optimistic messages, copy and cancellation improve the text interface while preserving native approvals and artifact cards.
- Stock imagery: uploaded covers take priority. Recipes without covers immediately use optimized bundled Pexels food photos and optionally resolve a closer match through an authenticated, workspace-scoped Pexels search endpoint. Requests are lazy and deduplicated, provider searches are cached for seven days, and failures retain local imagery. Sources and attribution URLs are validated. Stock photos are labeled and credited; they never alter canonical recipe media, private galleries or immutable shared snapshots.
- Retain the supplied specification filename unchanged.
- Use the current stable Next.js App Router. Load provider clients lazily so a build does not require live credentials; operations requiring missing configuration fail explicitly.
- Bundle Inter locally, avoiding a build-time external font dependency.
- Service worker caches only public assets and the offline document/scripts/styles. M5 stores explicit account-scoped recipe snapshots in IndexedDB; authenticated HTML and APIs remain uncached.
- TypeScript 6 and ESLint 9 are pinned to the versions supported by the current Next.js lint plugins (ESLint 10 fails in the upstream React plugin). Revisit on a compatible plugin release.
- Drizzle uses `pg` over PostgreSQL TCP for both Neon and local development, as supported by [Drizzle's Neon documentation](https://orm.drizzle.team/docs/connect-neon). Interactive transactions are required for bootstrap and later versioning. Production uses the Neon pooled connection string with TLS; local tests use isolated PostgreSQL 17, not an in-memory substitute.
- UUIDs throughout, timezone-aware UTC timestamps, membership indexes and foreign keys. User creation invokes transactional personal-workspace bootstrap; authenticated entry repairs an interrupted initial bootstrap idempotently. Removed memberships are never silently recreated.
- Better Auth owns session/password handling and database-backed auth rate limits. API and server-page boundaries derive identity from the session; each domain operation independently checks membership. Active-workspace metadata is not client-writable.
- Canonical recipe content is a validated JSONB snapshot on each version; source provenance and lifecycle live on the parent recipe. Updates lock the parent and compare the expected version to prevent lost edits. Restore appends a new version. Notes/favorites never create canonical versions.
- Library receives a compact workspace-scoped index for immediate client-side search. UI and server use the same exact/prefix/substring/tag/ingredient/note ranking. Full-text/trigram infrastructure is not needed for a personal cookbook at this stage; there is no arbitrary truncation of the searchable Library.
- Composite workspace/recipe foreign keys supplement service authorization. Reviewed M2's generated SQL and moved its supporting unique index before the dependent foreign keys (Drizzle emitted the reverse order).
- Imports converge on the same canonical schema and recipe/version services. Deterministic parsing runs without an LLM where possible; other text/image extraction uses AI SDK structured output through the centralized Anthropic/Gateway registry. The registry is introduced in M3 because extraction needs it; M4 supplies the conversational runtime.
- URL fetches validate every redirect and DNS answer, pin the validated address to the socket, reject private/local addresses and unsupported ports/content types, and bound bytes/time. Imported content is untrusted data with no extraction tools or model instruction authority.
- Inngest events and step results carry identifiers, not raw recipe text/photos. Jobs resolve the creator/workspace from the database, recheck membership, and idempotently create review drafts. Conflicting approval submissions fail rather than discard corrections. Generic recipe status changes cannot bypass draft review.
- R2 receives short-lived signed uploads under `uploads/workspaces/…`. Completion checks membership, validates actual image decoding/size, strips metadata, and publishes a unique immutable WebP under `workspaces/…` with a transaction-protected winner. Uploads and completion have separate atomic usage limits.
- Share tokens contain 256 bits of randomness and are stored only as SHA-256 hashes. Creation checks the displayed recipe version and cover; links expose that immutable snapshot and its selected image. Public HTML and images recheck the token, use no-store/noindex/no-referrer, and exclude private notes/history/raw sources. Revocation takes effect on subsequent requests.
- The authenticated route group owns one persistent assistant shell. Text requests contain only new user text or an approval decision plus claimed page identifiers; the server derives identity/workspace, validates the route and displayed recipe/version, and reconstructs all message/tool history from its database. Conversations are private to their creator, including within a shared workspace.
- The application runtime uses the stable native tool loop (8 steps, 60 seconds) and native approval parts. No client-provided tool arguments/results/history are accepted. Every tool invokes the same domain services. Archive approvals bind the current version, rechecked atomically before status changes.
- Conversation row locks/leases serialize turns; repeated request IDs cannot repeat mutations. A tool-call journal commits each mutation and its receipt in the same transaction. Server-side stream draining persists replies even after browser disconnect. Interrupted runs retain saved receipts and cannot overwrite later turns.
- Optional personal Gateway credentials are user-owned records encrypted with AES-256-GCM, fresh nonces, and user/provider-bound associated data. Only masked hints leave the service. Resolution is personal key, then application key. Imports and chat use the same resolution.
- Usage is recorded at model-call start and end, before tools run. Started/interrupted calls without reported charges remain unpriced, never assumed free. USD uses fixed decimal storage and integer summation. Deleting a conversation retains its usage rows. Automatic SDK retries are disabled to avoid untracked attempts; Inngest retries extraction as separately metered invocations. Gateway remains the authority for final billing, including interruptions/retries for which no charge reaches the app.
- AI SDK 7's streamed agent default can log raw provider errors; a stream error observer supplied through `prepareCall` replaces that default, and the UI stream has its own sanitized error handler. Regression tests verify billing errors are visible and private provider content is not logged. No custom fundamental agent loop is introduced.

- Cooking sessions pin an immutable recipe version through a composite workspace/recipe/version foreign key. Starting is explicit and concurrent starts resume the same active cook for that user/recipe. Progress uses a revision check under a row lock. History is workspace-readable; only the starter can change a cook or add its observations/photos. Optional wrap-up can be retried idempotently. Notes/photos never alter canonical content or cover images. Agent abandonment uses native confirmation and the same services.
- Offline storage retains at most 12 recent canonical recipes plus 8 cooking snapshots, within 24 MiB, with 512 KiB content and 2 MiB cover limits. Expiry is the earlier of the authenticated session expiry or seven days. A live authenticated scope check precedes cache population; sign-out, account switching and expiry clear data. Per-scope epochs block stale tabs and delayed image fetches from repopulating prior accounts. Offline checkoffs stay local with no synchronization queue; reconnecting reloads saved progress. Wake lock is optional and degrades gracefully.

- Conversation model selection is a nullable model ID separate from credentials. The central registry allowlists explicit choices; null follows the administrator’s AI_MODEL/default. Changes compare the prior selection and reject active replies/pending approvals. Each turn freezes its saved model under the conversation lock, and usage reports the actual invoked model. No automatic provider/model substitution occurs on failure.

- Artifacts belong to a workspace and persist as validated structured JSON with stable item IDs. Every mutation checks membership and the expected revision under a row lock. Grocery derivation reads authorized immutable recipe versions, scales deterministically, preserves wording and provenance, and does not guess unit aggregation. Meal entries pin versions while allowing described meals and optional dates. Copy/share sends text only on explicit user action; artifact URLs remain authenticated. No permanent Grocery or Plan navigation was introduced.
- Artifact mutation receipts contain only identity/title/kind/revision. Model reads page through complete rows with a 30 KB budget and revision/cursor metadata. The UI renders one current card per artifact, fetching authorized saved content; older receipts stay compact links, avoiding repeated full-list payloads. Storage limits are 1,000 grocery items, 100 groups, and 200 meal entries; individual external actions are further bounded. Offline artifact edits roll back without a synchronization queue.
- MCP uses the official MCP SDK and Better Auth MCP/OAuth/CIMD plugins. A fresh server instance handles each request; the SDK's stateless legacy mode also supports Claude's 2025 protocol. Signed access tokens last five minutes and are checked against the original consent, session, client and workspace membership on every request. Revocation immediately invalidates access tokens, refresh families and pending codes; reconnection cannot restore old grants. Signing keys remain encrypted with the server auth secret. Read and write scopes are independent; browser consent presents the exact signed request and registered callback.
- MCP creates structured imports through the existing draft/review pipeline without an LLM or Inngest job. A UUID request ID is bound to the user, workspace and OAuth client for idempotent retries; original structured content and trusted client provenance are retained. Drafts require review in Sift before MCP edits. Updates use complete validated content and an expected immutable version; there are no delete, archive, approval or publishing MCP tools. Writes are capped at 64 KB, protocol bodies at 256 KB, and large reads page complete rows with a 40 KB budget. Requests have per-user and per-client limits. External Claude usage is billed by Claude, not Sift's Gateway ledger.

- M7 uses a private ElevenLabs agent solely for speech transport and turn-taking. Its custom LLM callback invokes the existing Sift runtime and Gateway model selection; provider tools, backup LLMs, speculative turns and client configuration overrides are disabled. This preserves the specification's single-assistant architecture. The user selected the existing **George** British voice; no celebrity voice cloning or additional personality interface was introduced. Speech uses `eleven_flash_v2`: the live ElevenLabs Agents API rejected Flash v2.5 for an English agent and required Flash/Turbo v2; this does not change Sift's selected Gateway reasoning model. ElevenLabs custom LLM configuration uses the base URL `/api/voice/llm/`, while the actual authenticated callback remains `/api/voice/llm/chat/completions`. Two isolated deleted-session diagnostics established that its runtime appends `chat/completions`: configuring the full callback URL never reached the function; configuring the base URL produced the expected authenticated 401 responses. This agrees with the [official Cloudflare custom-LLM guide](https://elevenlabs.io/docs/eleven-agents/customization/llm/custom-llm/cloudflare), despite conflicting endpoint wording in the schema.

- Voice sessions bind the provider conversation ID to the authenticated Sift user, workspace, auth session and conversation before the browser connects. Each model step and tool execution rechecks authorization and the active voice turn. The browser renews a 60-second lease; sessions end after 30 minutes or auth-session expiry. New voice turns and explicit cancellation fence the prior voice-owned run while preserving committed tool receipts. Provider retries use a durable transcript fingerprint and the last completed reply instead of repeating mutations. The server accepts only new user speech from provider history and rebuilds trusted context from its own database. ElevenLabs may revise the latest user transcription without advancing its turn ordinal or user-message count. Sift validates the unchanged earlier history against its saved fingerprint and handles the revision under the voice-session and conversation locks. If no write or approval committed, it fences the superseded run and processes the corrected text. If a write or approval already exists, it preserves that result and records a spoken review notice instead of repeating the action. Native approval proposals remain resumable in the shared SDK history. Turn timestamps reflect reservation time under the lock so overlapping transactions cannot reorder the visible result.

- Voice usage is recorded from timestamped HMAC-signed post-call webhooks, with retries enabled on Sift's webhook. ElevenLabs USD cost, provider credits and duration are stored separately from Gateway model charges; missing costs remain unreported. Audio is not retained; provider transcript retention is seven days, and webhook payloads exclude transcript content. Auth-session and conversation deletion preserve usage accounting. Migration `0009_hesitant_tana_nile.sql` adds the voice session/turn records and has been applied to development, test and production databases (ten migrations total).
